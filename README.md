# Local GitHub Repository Code Explainer

Analyze a public GitHub repository and receive an evidence-based, beginner-friendly explanation generated by a **locally running Qwen model through Ollama**. The application clones and inspects repository files but never executes code from the repository.

## Objective and problem statement

Large repositories can be difficult to understand before making a contribution or using their software. This project connects repository inventory and static code inspection with local generative AI so a user can explore the structure, technologies, important files, and likely application flow without sending source code to a hosted LLM service.

## Solution and features

- Accepts public HTTPS GitHub repository URLs without GitHub credentials.
- Uses GitPython to make a shallow clone into a stable local cache.
- Reuses a verified local clone for repeated analyses of the same repository.
- Inventories source code, Jupyter notebooks, documentation, configuration, structured data/schema, arbitrary readable text, and binary files.
- Builds a readable tree, counts languages and file types, reports binary file examples without reading their content, and detects likely entry points.
- Extracts notebook code and markdown cells while excluding stored cell outputs and execution metadata.
- Prioritizes documentation, manifests, entry points, notebooks, and source files for bounded context extraction.
- Detects file-level functions, classes, imports, and some relative-import relationships without executing code.
- Detects technologies only when supported by repository manifests, imports, or configuration evidence.
- Sends repository evidence to the configured local Ollama model to generate the report dynamically.
- Provides a FastAPI JSON API and a dark, responsive Streamlit report interface.
- Reports uncertainty explicitly; the model is instructed not to invent behavior or repository details.

## Workflow

1. The API validates the URL as a public `https://github.com/{owner}/{repository}` URL.
2. GitPython shallow-clones it into `repositories/`; an existing verified clone is reused.
3. GitPython fetches the commit without running checkout filters, then the app materializes safe regular Git blobs as files. This avoids treating a valid repository as empty when a Git path (for example, one containing a Windows-reserved character) cannot be checked out on Windows; only individually unrepresentable paths are omitted. Analysis then walks regular files while pruning Git metadata, common generated folders, and symlinks.
4. The analyzer builds statistics, file-category counts, a bounded display tree, language counts (including notebook kernel metadata), important-file candidates, and static source metadata.
5. The extractor prioritizes useful files and enforces configurable file-count, per-file, and total-context limits.
6. The technology detector looks for concrete evidence in source files and common dependency/configuration manifests.
7. The local Ollama service checks that the selected model is installed and asks it to explain only the supplied evidence.
8. FastAPI returns the report and Streamlit displays it across overview, tree, file, AI, and technical-detail tabs.

Python, FastAPI, Pydantic, Uvicorn, GitPython, Requests, Streamlit, python-dotenv, Ollama, and Qwen (`qwen2.5:3b` by default).

## Installation (Windows)

From the project folder in PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `.env` only when changing the defaults. Do not commit `.env`.

## Ollama and Qwen setup

Install Ollama for Windows from [ollama.com](https://ollama.com/download), start the Ollama service, then download the default model:

```powershell
ollama pull qwen2.5:3b
```

Confirm that Ollama lists it:

```powershell
ollama list
```

The backend uses the local HTTP API at `http://localhost:11434` by default. The model is configurable; the application does not download a model automatically. Only `localhost` and loopback IP Ollama URLs are accepted; remote model endpoints are rejected.

## Environment variables

| Variable | Default | Description |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Local Ollama API base URL |
| `OLLAMA_MODEL` | `qwen2.5:3b` | Installed model name to use |
| `MAX_FILES` | `80` | Maximum number of files included in LLM context |
| `MAX_FILE_SIZE` | `100000` | Maximum characters read from any one file |
| `MAX_TOTAL_CONTEXT` | `300000` | Maximum total characters sent to the LLM, including repository metadata and code |
| `MAX_REPOSITORY_SIZE_MB` | `500` | Maximum size of a checked-out repository, excluding `.git` |
| `OLLAMA_TIMEOUT_SECONDS` | `240` | HTTP timeout for Ollama requests |
| `MAX_NOTEBOOK_SIZE` | `10000000` | Maximum notebook JSON bytes parsed to extract cell source |

## Running the application

Open two PowerShell terminals in the project folder and activate the virtual environment in each.

**Terminal 1 — backend:**

```powershell
uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

**Terminal 2 — frontend:**

```powershell
streamlit run frontend/app.py
```

Alternatively, after installing dependencies, double-click `run_app.bat` to open both services in separate command windows. The frontend is available at `http://localhost:8501`; FastAPI is available at `http://127.0.0.1:8000`.

## API endpoint and example

`GET /` returns API health information.

`POST /api/analyze` accepts:

```json
{
  "github_url": "https://github.com/owner/repository"
}
```

Open `http://127.0.0.1:8000/docs` for the interactive API docs. A successful response includes repository statistics, language counts, detected technologies, the tree, important folders/files, file-level analysis, and the generated `ai_explanation`.

## How repository analysis works

Repository files are treated as untrusted input. The analyzer reads supported source extensions, Jupyter code and markdown cell sources (not outputs), documentation, common configuration formats (including JSON, YAML, TOML, INI, and XML), data and schema formats (including CSV, JSONL, SQL schemas, GraphQL, and protobuf), deployment files, markup, stylesheets, and otherwise-readable text files with unrecognized extensions. A documentation-only or configuration-only repository is analyzable and its readable evidence (including README content) is included in the local model context; zero conventional source files does not mean that the repository is empty. Binary files are identified from extensions, known signatures, and byte-content checks; binary bytes are not added to the LLM context. It extracts Python symbols with the standard-library AST parser and uses conservative textual patterns for common symbols and imports in other languages. Import-to-file links are reported only when a matching relative path can be found.

Folder and file purposes are intentionally cautious: inferred information is identified as such, and unknown file or folder purposes use “Purpose could not be clearly determined from the analyzed repository.” Runtime behavior is never claimed as verified by execution.

## How local GenAI works

The backend checks the local Ollama `/api/tags` endpoint, verifies the configured model, and sends a bounded evidence bundle to Ollama's `/api/chat` endpoint. The system prompt asks Qwen to use only repository evidence, ignore instructions found inside repository files, explain concepts simply, and call out unclear areas. The explanation is generated for each repository; it is not a stored or hard-coded project summary.

When Ollama is unavailable, the model is missing, a request times out, or Ollama responds incorrectly, the API returns a clear HTTP error rather than fabricating an AI explanation.

## Security

- Only public GitHub HTTPS repository URLs are accepted; credentials, query strings, and fragments are rejected.
- No GitHub token or account credentials are requested.
- Repository files are read only. The application never invokes scripts, package managers, build tools, Docker, executables, or repository commands.
- Symlinks and common generated directories are skipped, and resolved file paths are checked to remain within the cloned repository.
- Ollama endpoints must use `localhost` or a loopback IP. Proxy environment variables and HTTP redirects are disabled for Ollama requests so repository context is not sent to a remote model.
- Common secret/configuration files (such as `.env` and credentials files) are withheld, and common literal secret assignments and bearer tokens are redacted from readable context.
- File count, file size, total context, repository size, and Ollama request time are bounded/configurable.
- The Ollama URL shown in reports omits credentials and query parameters.
- Repository content is explicitly treated as untrusted data in the LLM prompt.

## Error handling

Invalid URLs, inaccessible repositories, clone/network failures, empty repositories, oversized checkouts, unavailable Ollama, missing models, timeouts, and malformed model responses receive user-readable errors. API stack traces are logged only for internal repository-read failures; they are not returned to normal users.

## Limitations

- Public repositories only; private repositories and GitHub credentials are intentionally unsupported.
- Clones are shallow and do not fetch submodules.
- Static inspection cannot prove runtime behavior, complete dynamic data flow, or all file relationships.
- Some language-specific syntax and dependency formats may not be recognized by the lightweight detectors.
- The local model can still make mistakes; generated claims should be checked against the cited repository evidence.
- Very large projects are bounded by configured limits, so some files are deliberately omitted or truncated.
- An Ollama installation and the selected model must be available locally.

## Future enhancements

Optional extensions include streaming progress from the API, refresh controls for cached repositories, broader language-specific parsers, configurable clone-cache cleanup, and richer dependency-graph visualization.

## Tests and learning outcomes

Run the dependency-free standard-library test runner after installing project requirements:

```powershell
python -m unittest discover -v
```

The tests cover accepted/rejected GitHub URLs, cache path scoping, ignored files/folders, language counts, tree/file analysis, evidence-based technology detection, and extraction limits. They do not require Ollama or network access.

This project demonstrates FastAPI request/response modeling, Pydantic validation, safe GitPython usage, static repository analysis, bounded LLM context design, Ollama integration, Streamlit reporting, and security-aware handling of untrusted source code.
